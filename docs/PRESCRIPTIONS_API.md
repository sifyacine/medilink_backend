# Prescriptions API Documentation

## Overview

The Prescriptions API enables doctors to create, manage, and issue prescriptions for patients after confirmed or completed appointments. The system supports:

- **Doctor-issued prescriptions** linked to appointments
- **Prescription items** (medications) with detailed dosage instructions
- **PDF file storage** (generated by frontend)
- **Patient and clinic associations**
- **Full prescription history tracking**

---

## Authentication & Authorization

All endpoints require JWT authentication. Permission enforcement is role-based:

### Role Hierarchy

| Role | Permissions |
|------|-------------|
| **Doctor** | Create, read, update, delete own prescriptions |
| **Patient** | Read own prescriptions only |
| **Admin** | Full access to all prescriptions |

### Provider Relationship Chain

**Important:** The system uses a layered provider structure:
```
User → provider_profile (Provider) → doctor_profile (Doctor)
```

A doctor is only authorized if:
1. User has a `provider_profile`
2. Provider has `status = APPROVED`
3. Provider has a `doctor_profile`

## Data Models

### Prescription

| Field | Type | Description |
|-------|------|-------------|
| `id` | UUID | Unique identifier |
| `reference_number` | String | Human-readable reference (e.g., `RX250619-ABC123`) |
| `doctor` | FK → Doctor | Issuing doctor (required) |
| `patient` | FK → User | Patient with account (mutually exclusive with patient_record) |
| `patient_record` | FK → PatientRecord | Patient without account |
| `clinic` | FK → Clinic | Optional clinic association |
| `appointment` | OneToOne → Appointment | Required, must be CONFIRMED or COMPLETED |
| `diagnosis` | Text | Diagnosis or reason for prescription |
| `notes` | Text | Additional prescription notes |
| `instructions` | Text | General patient instructions |
| `pdf_file` | File | Uploaded PDF (generated by frontend) |
| `status` | Enum | DRAFT, ISSUED, DISPENSED, EXPIRED, CANCELLED |
| `valid_until` | Date | Expiration date |
| `issued_at` | DateTime | When prescription was issued |
| `created_at` | DateTime | Creation timestamp |
| `updated_at` | DateTime | Last modification timestamp |

### PrescriptionItem

| Field | Type | Description |
|-------|------|-------------|
| `id` | UUID | Unique identifier |
| `prescription` | FK → Prescription | Parent prescription |
| `medication_name` | String | Medication name (required) |
| `medication_type` | Enum | TABLET, CAPSULE, SYRUP, INJECTION, etc. |
| `generic_name` | String | Generic medication name |
| `strength` | String | Medication strength (e.g., "500mg") |
| `dosage` | String | Dosage instructions (e.g., "1 tablet") |
| `frequency` | Enum | ONCE_DAILY, TWICE_DAILY, AS_NEEDED, CUSTOM, etc. |
| `custom_frequency` | String | Custom frequency text (when frequency=CUSTOM) |
| `duration_days` | Integer | Treatment duration in days |
| `duration_text` | String | Human-readable duration |
| `quantity` | Integer | Total quantity prescribed |
| `quantity_unit` | String | Unit (e.g., "tablets", "ml") |
| `instructions` | Text | Special instructions |
| `order` | Integer | Display order |

### Prescription Status Flow

```
DRAFT → ISSUED → DISPENSED
  ↓                  
CANCELLED          EXPIRED (automatic via valid_until)
```

## API Endpoints

### Base URL: `/api/prescriptions/`

### Create Prescription

**POST** `/api/prescriptions/`

Creates a new prescription. Only accessible by approved doctors.

**Headers:**
```
Authorization: Bearer <jwt_token>
Content-Type: application/json
```

**Request Body:**
```json
{
  "patient_id": "uuid-of-patient",
  "appointment_id": "uuid-of-appointment",
  "clinic_id": "uuid-of-clinic",
  "diagnosis": "Viral upper respiratory infection",
  "notes": "Patient presents with cold symptoms for 3 days",
  "instructions": "Complete full course of antibiotics. Rest and hydrate.",
  "valid_until": "2025-07-19",
  "items": [
    {
      "medication_name": "Amoxicillin",
      "medication_type": "CAPSULE",
      "generic_name": "Amoxicillin",
      "strength": "500mg",
      "dosage": "1 capsule",
      "frequency": "THREE_TIMES_DAILY",
      "duration_days": 7,
      "quantity": 21,
      "quantity_unit": "capsules",
      "instructions": "Take with food"
    }
  ]
}
```

**Response (201 Created):**
```json
{
  "id": "uuid-of-prescription",
  "reference_number": "RX250619-XYZ789",
  "patient_id": "uuid-of-patient",
  "patient_name": "John Doe",
  "doctor_id": "uuid-of-doctor",
  "doctor_name": "Dr. Jane Smith",
  "clinic_id": "uuid-of-clinic",
  "clinic_name": "Downtown Medical Center",
  "appointment_id": "uuid-of-appointment",
  "diagnosis": "Viral upper respiratory infection",
  "notes": "Patient presents with cold symptoms for 3 days",
  "instructions": "Complete full course of antibiotics. Rest and hydrate.",
  "status": "DRAFT",
  "status_display": "Draft",
  "valid_until": "2025-07-19",
  "items": [...],
  "created_at": "2025-06-19T10:30:00Z"
}
```

**Validation Rules:**
- `patient_id` or `patient_record_id` required (mutually exclusive)
- `appointment_id` required; appointment must be CONFIRMED or COMPLETED
- One prescription per appointment
- `items` array is optional at creation (can add later)

**Error Responses:**
- `400 Bad Request` - Validation errors
- `401 Unauthorized` - Missing or invalid token
- `403 Forbidden` - User is not an approved doctor

### List Prescriptions

**GET** `/api/prescriptions/`

Returns prescriptions based on user role:
- **Doctors**: Their own prescriptions
- **Patients**: Prescriptions for them
- **Admins**: All prescriptions

**Query Parameters:**
| Parameter | Type | Description |
|-----------|------|-------------|
| `status` | string | Filter by status (DRAFT, ISSUED, etc.) |
| `ordering` | string | Order by field (default: `-created_at`) |
| `page` | integer | Pagination page number |

```json

  "count": 25,

      "clinic_name": "Downtown Medical Center",

      "status_display": "Issued",

      "issued_at": "2025-06-19T11:00:00Z",
```

### Update Prescription

**PUT/PATCH** `/api/prescriptions/{id}/`

Update a prescription. Only the issuing doctor can update, and only while in DRAFT status.

**Request Body (PATCH):**
```json
{
  "diagnosis": "Updated diagnosis",
  "instructions": "Updated instructions"
}
```

**Response (200 OK):** Updated prescription object

**Constraints:**
- Only DRAFT prescriptions can be updated
- Only the doctor who created it can update

---

### Delete Prescription

**DELETE** `/api/prescriptions/{id}/`

Delete a prescription. Only works for DRAFT status.

**Response (204 No Content)**

---

### Issue Prescription

**POST** `/api/prescriptions/{id}/issue/`

Change prescription status from DRAFT to ISSUED. Sets `issued_at` timestamp.

**Response (200 OK):** Updated prescription with status ISSUED

**Constraints:**
- Prescription must be in DRAFT status
- Only the issuing doctor can perform this action

---

### Cancel Prescription

**POST** `/api/prescriptions/{id}/cancel/`

Cancel a prescription.

**Response (200 OK):** Updated prescription with status CANCELLED

---

### Upload PDF

**POST** `/api/prescriptions/{id}/upload-pdf/`

Upload a PDF file for the prescription (generated by frontend).

**Headers:**
```
Authorization: Bearer <jwt_token>
Content-Type: multipart/form-data
```

**Request Body:**
```
pdf_file: <file>
```

**Response (200 OK):** Updated prescription with pdf_file URL

---

### Manage Prescription Items

**GET** `/api/prescriptions/{id}/items/`

List all items in a prescription.

**POST** `/api/prescriptions/{id}/items/`

Add a new item to a prescription.

**Request Body:**
```json
{
  "medication_name": "Ibuprofen",
  "medication_type": "TABLET",
  "strength": "400mg",
  "dosage": "1 tablet",
  "frequency": "AS_NEEDED",
  "quantity": 20,
  "quantity_unit": "tablets",
  "instructions": "Take with food as needed for pain"
}
```

**Constraints:**
- Only DRAFT prescriptions can have items added

## Common Use Cases

### 1. Doctor Creates Prescription After Appointment

```
1. GET /api/appointments/{id}/ → Verify CONFIRMED/COMPLETED status
2. POST /api/prescriptions/ → Create with appointment_id
3. POST /api/prescriptions/{id}/items/ → Add medications (optional)
4. POST /api/prescriptions/{id}/issue/ → Issue prescription
5. POST /api/prescriptions/{id}/upload-pdf/ → Upload generated PDF
```

### 2. Patient Views Their Prescriptions

```
1. GET /api/prescriptions/my-prescriptions/ → List all
2. GET /api/prescriptions/{id}/ → View details
```

### 3. Doctor Reviews Prescription History

```
1. GET /api/prescriptions/my-issued/ → List issued prescriptions
2. GET /api/prescriptions/my-issued/?patient_id=xxx → Filter by patient
```

---

## Notes

1. **PDF Generation**: The frontend is responsible for generating PDFs. The backend only stores the uploaded file.

2. **Prescription Uniqueness**: Each appointment can have at most one prescription (OneToOne relationship).

3. **Patient Types**: Supports both users with accounts (`patient` field) and patient records (`patient_record` field).

4. **Provider Approval**: Only doctors with `APPROVED` provider status can create prescriptions.

5. **Immutability**: Once issued, prescriptions cannot be modified (only cancelled).
